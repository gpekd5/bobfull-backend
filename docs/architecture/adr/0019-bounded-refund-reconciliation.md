# ADR 0019: 환불 정합성 재조정을 유한 자동화로 제한

- 상태: `Accepted`
- 작성일: `2026-08-18`
- 관련 Issue·PR: #141, #272, PR #279
- 주요 근거: Issue #272 최종 계약, PR #279 구현·테스트 Evidence

## 배경

외부 PG 환불 요청은 네트워크·외부 상태 확인 지연 때문에 내부 `Refund`가 `REQUESTED` 또는 `PROCESSING`에 오래 머물 수 있다. BobFull은 `RefundReconciliationScheduler`가 이런 환불을 주기적으로 PortOne에 재조회해 내부 상태를 다시 맞추는 복구 경로를 사용한다.

하지만 외부 결제 자체가 영구히 매칭되지 않는 등 자동으로 해결할 수 없는 건까지 무한 재시도하면 PortOne API 호출과 DB 작업이 계속 발생한다. #272 논의에서 이를 단순 로컬 로그 노이즈가 아니라 **운영에서도 발생 가능한 복구 정책의 공백**으로 판단했다.

## 문제

자동 재조정을 언제까지 계속할지 경계가 없으면 다음 문제가 생긴다.

- 영구 미매칭 환불에 외부 API 호출이 무기한 반복됨
- 해결 가능성이 낮은 건과 일시적 지연 건의 운영 경계가 없음
- 자동화가 끝나고 사람이 확인해야 하는 시점을 명확히 정하기 어려움

반대로 너무 이르게 자동 재조정을 중단하면 일시적 PG 지연을 사람이 불필요하게 처리해야 한다.

## 고려한 대안

### 무기한 자동 재시도 유지

- 구현이 가장 단순하다.
- 일시적 장애가 오래 지속돼도 자동 복구 가능성을 계속 유지한다.
- 영구 미매칭 건에서도 PortOne 조회와 DB 처리가 끝없이 반복된다.
- 자동화에서 Human 운영으로 넘어가는 종료 경계가 없다.

### 재시도 횟수·상태를 Refund에 영속화

예: 별도 attempt count, `ESCALATED` 같은 상태를 추가한다.

- 종료 사유와 운영 상태를 명시적으로 표현할 수 있다.
- Refund 상태 모델과 스키마를 확장해야 하고 기존 상태 전이 전체를 다시 검토해야 한다.
- 이번 문제는 후보 조회 범위를 제한하는 것만으로 해결할 수 있어 과한 변경으로 판단했다.

### 시간 상한 + 기존 운영 알림 재사용

- 일정 시간까지는 자동 재조정을 계속한다.
- 상한을 넘기면 자동 후보에서 제외한다.
- 기존 장기 미해결 ERROR 로그를 Human 확인 신호로 재사용한다.
- 새 상태나 컬럼은 추가하지 않는다.

## 결정

환불 정합성 재조정은 **무한 자동화가 아니라 시간 상한이 있는 유한 자동화**로 운영한다.

현재 기본 계약은 다음과 같다.

```text
REQUESTED / PROCESSING Refund
        ↓
최소 대기 시간 경과
        ↓
Scheduler가 PortOne 재조회
        ↓
일시적 문제면 다음 주기에 재시도
        ↓
max-age 기본 24시간 초과
        ↓
자동 재조정 후보에서 제외
        ↓
기존 ERROR 신호를 기준으로 Human 확인
```

- `payment.refund-reconciliation.max-age` 기본값은 24시간이다.
- `max-age`를 넘긴 `REQUESTED`/`PROCESSING` 환불은 재조정 후보 조회에서 제외한다.
- `Refund` 상태를 강제로 다른 값으로 바꾸지 않는다.
- 별도 attempt count나 종료 컬럼을 추가하지 않는다.
- 60분 경과 시 기존 `REFUND_RECONCILIATION_REQUIRED` ERROR 로그를 Human 확인이 필요한 운영 신호로 계속 사용한다.
- 로컬에서는 스케줄러를 기본 비활성화하고, 설정이 명시되지 않으면 생성되지 않도록 `matchIfMissing=false`를 사용한다. 이는 운영 종료 정책과 별개의 개발환경 기본값이다.

24시간은 코드에 고정된 불변 도메인 규칙이 아니라 현재 운영 기본값이며 설정으로 조정할 수 있다.

## 선택 이유

#272에서 담당자와 논의해 무한 재시도를 운영 설계 공백으로 분류했고, 새로운 상태 모델을 도입하는 대신 **자동 복구가 의미 있는 시간 구간까지만 재시도하고 이후 Human 운영으로 책임을 넘기는 경계**를 선택했다.

PR #279에서는 다음을 검증했다.

- `max-age`보다 오래된 Refund가 후보에서 제외됨
- 기존 상태·최소 나이·재확인 지연·정렬 동작이 유지됨
- `enabled` 미지정/false/true에 따른 Scheduler Bean 생성 조건이 의도대로 동작함
- 전체 테스트 통과

실제 운영 PortOne 호출량 감소를 별도 성능 수치로 측정한 것은 아니므로 정량 비용 절감 효과를 주장하지 않는다.

## 장점

- 해결 가능성이 낮은 환불에 대한 무한 외부 API 호출을 막는다.
- 기존 Refund 상태 모델과 스키마를 유지한다.
- 자동 복구와 Human 확인의 책임 경계를 명확히 한다.
- `max-age`를 설정으로 조정할 수 있다.

## 단점과 위험

- `max-age` 초과 시 별도의 terminal Refund 상태가 남지 않는다.
- 상한을 막 넘기는 순간 전용 "자동 재조정 종료" 로그를 새로 남기지 않는다.
- Human이 기존 ERROR 로그와 운영 조회를 확인해야 한다.
- 24시간 이후에도 자동으로 복구될 수 있었던 외부 지연 건은 수동 확인 대상으로 넘어간다.

## 검증 방법

- `max-age` 초과 Refund가 `findReconciliationCandidates` 결과에서 제외되는지 테스트
- 기존 재조정 상태 필터·최소 나이·재확인 지연·정렬 회귀 테스트
- Scheduler `enabled` 미지정/false/true 조건 테스트
- 전체 build/test 통과

상세 구현·검증은 #272와 PR #279를 기준으로 한다.

## 재검토 조건

- 장기 미해결 Refund가 운영에서 자주 발생할 때
- Human 확인 건수가 증가해 별도 `ESCALATED` 상태나 운영 Queue가 필요할 때
- max-age 초과 시 명시적 알림·대시보드·수동 재처리 도구가 필요할 때
- PG 특성상 24시간을 넘는 정상 지연이 실제로 관측될 때
